Internet 总述

物理组成 - a "nuts and bolts" view

所有的终端设备被称为主机（host）或端系统（end system），不同设备通过通信链路，借助分组交换机（packet switch）进行链接。从发送端到接收端，一个 packet 所经历的一系列通信链路和分组交换机的序列即路径 Route

数据会被发送端系统分段，并且给每个段添加 header bytes，组装在一起就是一个 packet，被用于实际的传输，由接收端进行原始数据的装配

分组交换机的作用是从一条入链路接收 packet，从一条出链路转发packet。常见的分组交换机包括

  • 路由器 Router，在网络层工作，根据 IP 地址决定转发去向
  • 交换机 Switch，在链路层工作，根据 MAC 地址决定转发去向

路由器让多个设备所在的局域网能够与公网互通；交换机让多个设备接入同一局域网

事实上现在的家用路由器通常综合了这两个功能 + NAT 功能

端系统通过多级的 Internet Service Provider（ISP）接入 Internet。每个 ISP 网络都是独立管理的，运行着 IP 协议，遵从一定的命名和地址规则

位于相同等级结构层次的邻近的一对 ISP 是对等的；因特网交换点 IXP 可以让多个 ISP 一起对等

而从物理构成来看，Internet 可以概括为 Network of Networks，如图所示

服务描述 - a "services" view

从服务的角度来看，Internet 是一个为各种分布式应用提供通信服务的基础设施，通过编程接口向应用提供 Hooks，允许收发程序借此进行连接，或者使用 Internet 交换服务

套接字 Socket 是应用层与传输层的接口，是应用程序使用 Internet 传输服务的唯一入口，对 APP 开发者是向下透明的

协议

协议（protocol）定义了在两个或多个通信实体之间交换的 packet 的格式和顺序，及其发送/接收或其他事件所采取的操作

各个部件交流都需要协议 Protocol，这些协议控制 Internet 中信息的接收和发送。Internet 的主要协议统称为 TCP/IP，分为传输控制协议（Transmission Control Protocol）和网际协议（Internet Protocol）两部分

为了让 Internet 协议及其实际作用取得共识，IETF 提出了 Internet Standard，对应的标准文档为请求评论（Request For Comment，RFC），它定义了各种互联网相关的协议，也包括 HTTP、SMTP 之类

Network Edge

我们把 Internet 区分为“边缘”与“核心”。其中 Network Edge 包括两个部分：端系统 + 与公网连接的最近一层网络（接入网 Access Networks）

Access Networks: The network that connects an end system to the first router (aka “edge router” 边缘路由器)

相对的我们有 Network Core，对应的位置大概如下

End systems 又被称为 hosts，进一步的又根据用途分为 clients 和 servers，而 servers 通常将数据存放在 data centers

Access Networks

接入网络主要分为三类：家庭接入、企业/校园接入、广域移动无线接入

家庭接入主要包括 DSL（数字用户线）、Cable 电缆接入、FTTH（光纤到户）；近年还有 FWI（固定无线接入）和 LEO 低轨卫星接入（比如 Starlink）

企业/校园接入主要包括以太网 Ethernet（比如局域网 LAN）、WiFi，进一步的。通过将家庭接入方式与 LAN 等进行结合，构建家庭网络

广域移动无线接入主要为 4G 与 5G

Physical Media

物理媒介即 bit 在发送器-接收器对之间传输时，所经过的物理介质，分为导引型媒介（guided media）和非导引型媒介

导引型媒介包括双绞铜线、同轴电缆、光纤等

非导引型媒介包括地面无线电信道、卫星无线电信道

Network Core

Network Core 是由分组交换机和链路构成的网状网络。通过网络链路和交换机移动数据有两种基本方法：分组交换（Packet switching）与电路交换（Circuit switching）

Circuit switching

先讨论早期的形式

如果我们为通信会话预留资源，通过专门的连接进行通信，那么我们称这个独占连接为“电路”，电路的传输速率是恒定的（预留带宽），因此发送方能够以恒定速率向接收方传送数据。下图是一个电路交换网络，因为端到端连接是专用的，所以每种连接方式都预留一条电路，并获得链路总传输容量的固定比例

上述的“电路”并不是物理意义上的。一条物理链路如何同时承载多条电路？考虑频分复用（FDM）或时分复用（TDM）

FDM 将链路的频谱划分为多个频段，让每条链接独占某个频段，使得每条电路连续地得到部分带宽且无打扰

TDM 将时间切片，以帧 Frame 为单位。对于每一个 Frame，切分固定数量的时隙 time slots，然后在每个帧中为某个连接指定一个时隙，某个时隙由某个连接单独使用

Packet switching

互联网本身采用分组交换。简单描述一个 packet 从源到目的地的相关内容

转发表

首先，路由器如何决定一个 packet 的转发去向？每个端系统都有 IP 地址，之前提到过发送端会给 packet 添加 header bytes，其中包含了目的地的 IP 地址

当一个 packet 到达网络中的路由器时，路由器检查该 packet 的目的地址的一部分，并向一台相邻的路由器转发该 packet。具体的，每台路由器具有一个转发表（forwarding table），用于将目的地址 （或一部分）映射为输出链路。当某 packet 到达一台路由器时，路由器检查该地址，并用这个目的地址搜索其转发表，以发现适当的出链路。路由器再将 packet 导向该出链路

至于转发表的设置等，参考后面的内容

存储转发传输

当 packet 经过整条 route 传输时，以等于该链路最大传输速率的速度通过通信链路。考虑 L bit 的 packet ，而链路的传输速率为 R bps，则传输该 packet 的时间为 L/R s

大多数分组交换机在链路的输入端使用存储转发（store-and-forward）传输机制，指在交换机开始向输出链路传输该 packet 的第一个比特之前，必须接收到整个 packet （而不是收到一部分就发一部分）。显然，对于包含 \(N-1\) 台路由器的链路（\(N\) 条速率均为 \(R\) 的链路）组成的路径，端到端时延为

\[ d_{\text{end-to-end}} = N\dfrac{L}{R} \]

排队时延和分组丢失

通常，每台分组交换机存在多条线路与之相连。分组交换机为每条相连的线路准备了一个输出缓存，用于存储路由器准备发往链路的 packets

它的作用是显然的：如果到达的 packet 需要传输到某条链路，但发现该链路正忙于传输其他 packets，该 packet 必须在输出缓存中等待（因此输出缓存是一个队列）

也因此，除了存储转发时延以外，packet 还要承受输出缓存的排队时延 （queuing delay）

进一步的，输出队列大小有限，如果某个 packet 到达时发现队列已满，则根据调度规则将这个到达的 packet 或正在队列内的 packet 进行丢弃。我们称之为丢包（packet loss）

Compare

分组交换的性能普遍优于电路交换

电路交换的独占特性，使得带宽只能被静态分配；而分组交换基于统计复用，类比操作系统的虚拟空间，可以针对每个人的使用频率来“超分配带宽”

比如 35 个人共享带宽，每个人在某时刻活跃的概率 \(p=0.1\)，则超过 10 个人同时活跃的概率为 $$ 1 -\sum_{k=0}^{10} \binom{35}{k} (0.1)^k (0.9)^{35-k} \approx 0.0004 $$ 因此分组交换允许更多的用户共享网络，且性能几乎不受影响

Measurement

进一步的，以分组连接为例，我们需要量化网络性能

Delay

当一个 packet 从一台路由器传输到下一台路由器时，会经历下面的时延：

\[ d_{\text{nodal}} = d_{\text{proc}} + d_{\text{queue}} + d_{\text{trans}} + d_{\text{prop}} \]
  • \(d_{\text{proc}}\) 为处理时延，包括 header 与纠错码校验，查表转发等
  • \(d_{\text{queue}}\) 为排队时延，是最复杂、不可预测的
  • \(d_{\text{trans}}\) 为传输时延，\(d_{\text{trans}} = L/R\)
  • \(d_{\text{prop}}\) 为传播时延，是在介质中实际传播的时间（并不是带宽相关）

经过 \(N\) 台路由器的端对端时延为

\[ d_{\text{end-end}} = N \times (d_{\text{proc}} + d_{\text{trans}} + d_{\text{prop}}) \]

注意到这里不包括排队时延，因为它的影响动态且复杂，而其他几项都是较为固定的（也就是说我们理想化了阻塞情况）

可以使用 Traceroute 软件进行简单的追踪

Loss

“排队”是非常普遍的现象，考虑 packet 长度 \(L\)，到达速率 \(a\)，链路传输速率为 \(R\)。显然我们应该比较

\[ \dfrac{La}{R} \sim 1 \]

如果这个比例超过了 1，那么时延会趋向正无穷；越接近 1，流量波动对排队时延的影响就越明显。我们希望 \(La/R\) 较小，这说明不需要进行长时间排队

排队的直接代价就是丢包 Loss

Throughput

吞吐量是另外一个层面。我们考虑路径上各个链路的传输速率 \(R_{i}\)，显然

\[ \text{Throughput} = \min\{R_1, R_2, \dots, R_N\} \]

在现代互联网中，瓶颈通常位于接入网（宽带）或者共享的核心链路。某处链路的卡脖子现象会直接影响整个路径的“网速”

总的来说，可以用固定时延（delay）、拥堵情况（loss）、吞吐量（Throughput）去量化网络性能

Layering && Encapsulation

终于来到计网的一个核心部分：分层与封装

一个复杂的结构必然需要分层，好处在于：

  • 模块化（Modularity）
  • 解耦（Decoupling）
  • 显然，这样做是为了让每次改动都是精确的、最小化的
  • 易于维护更新

互联网将复杂的通信过程划分为 5 个层次，自顶向下分为：

  • 应用层（Application Layer）：主要负责定义网络应用程序之间交换数据的规则和消息格式（HTTP SMTP 等）
  • 运输层（Transport Layer）：进程到进程的逻辑通信（TCP UDP 等，不是主机层面的）
  • 网络层（Network Layer）：把数据包 datagrams 从源主机路由到目的主机（IPv4 等）
  • 链路层（Link Layer）：在相邻的网络元素之间传输数据（WiFi 等）
  • 物理层（Physical Layer）：在物理介质上传输 bit（电信号、光信号等）

我们给出一个自顶向下的简单情景：

  • 应用层产生一个报文 Message，记为 \(M\)
  • 数据下传到运输层，运输层为报文添加运输层 Header，存储端口号等内容用于进程间通信，记为 \(H_t\)
  • 形成了运输层报文段 \([H_t\mid M]\)
  • 网络层接收 \([H_t\mid M]\)，也加上自己的 Header，包含 IP 地址等用于主机间通信，记为 \(H_n\)
  • 形成了网络层报文段 \([H_n\mid H_t\mid M]\)
  • 链路层接收 \([H_n\mid H_t\mid M]\)，也加上自己的 Header，包含 MAC 地址等用于在相邻设备间通信，记为 \(H_l\)
  • 形成了链路层报文段 \([H_l\mid H_n\mid H_t\mid M]\)
  • 之后进入物理层进行实际传输。对于接收端，它实施解封装（Decapsulation），即自底向上拆开报文段的头（每一层负责拆开对应的 Header 并处理），最终得到原始的 \(M\)

每一层的 Header 都是为了帮助对应层完成它的任务。下层把上层的数据当作有效载荷，并且附加自己的 Header 并下传

特别的，交换机 Switch 只会处理物理层+链路层，而路由器 Router 还会处理到网络层。这解释了为什么路由器可以连接不同的网络，而交换机通常只能在同一网络内工作
