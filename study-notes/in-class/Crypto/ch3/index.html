Lecture 3. Computational Security

我们常说的安全包括两类安全：

  • 信息论安全：即使攻击者拥有无限计算能力，密文也不会提供关于明文的额外信息（也就是完美保密性）
  • 计算安全：不再考虑具有无限计算能力的攻击者，而是仅要求系统能够抵抗高效攻击者，只允许攻击者具有可忽略的成功概率或区分优势

RSA 加密算法就是典型的计算安全，因为具有无限计算能力的攻击者可以做到手撕大数分解

为什么我们优先考虑计算安全的算法？因为完美保密算法的开销往往很大（至少要求 \(|\mathcal K|\geq|\mathcal M|\)），我们希望在降低开销的同时，以现有的人类科技无法在多项式时间内实现攻击

具体的，计算安全有两类定义方法：

  1. 具体安全方法（Concrete Approach）：直接讨论给定资源下，攻击成功概率的具体上界
  2. 渐近安全方法（Asymptotic Approach）：研究安全参数不断增大时，攻击复杂度与成功概率如何变化

我们只分析渐近安全方法

Prerequisites

我们需要先引入一些定义 / 概念等

PPT Algorithm

提出一类算法：PPT Algorithm（概率多项式时间算法）

  • 它允许使用随机性，比如随机猜测密钥
  • 它在多项式时间内运行

我们提到的高效攻击者，使用的攻击算法就是 PPT Algorithm

Security Parameter

我们引入一个安全参数 \(n\in\mathbb N^+\)，它往往与选用的密钥长度相关，并通常与加密系统的安全系数正相关。对安全属性参数化的好处是可以在安全性与计算成本之间进行权衡

从数学上，我们研究一系列方案：

\[ \Pi_n,\quad n=1,2,3,\ldots \]

并分析随着 \(n\) 增大，攻击者付出的计算资源和成功概率会有什么变化

Negligible Probability

我们首先定义超多项式增长：如果一个 \(f(n)\)，对于任意 \(c >0\)，都能找到足够大的 \(N_c\)，使得 \(\forall n > N_c\)

\[ f(n) > n^c \]

则函数 \(f(n)\) 具有超多项式增长，其增长速度最终会超过任何固定次数的多项式

反过来，考虑函数 \(\mu(n)\)，如果对于任意正多项式 \(p(n)\)，都存在某个整数 \(N\)，使得：

\[ \forall n>N,\qquad \mu(n)<\frac1{p(n)} \]

那么称 \(\mu\) 为可忽略函数（Negligible Probability），我们记为 \(\mu(n)=\operatorname{negl}(n)\)

它有一个与超多项式增长相近的定义：一个 \(\mu(n)\)，对于任意 \(c >0\)，都能找到足够大的 \(N_c\)，使得 \(\forall n > N_c\)

\[ \mu(n)<\frac1{n^c} \]

显然，可忽略函数最终会比任何逆多项式下降得更快

判断一个函数是不是可忽略函数，通常可以通过计算

\[ \lim_{n \to \infty} f(n) \cdot n^c = 0 \]

判断它是否对任意 \(c>0\) 都成立，如果是则为可忽略函数

我们给出一个常见的速查表格

\[ \begin{aligned} &\textbf{Negligible:} && 2^{-n},\ 2^{-\sqrt{n}},\ n^{-\log n},\ 2^{-(\log n)^2},\ \frac{1}{n!},\ n^{-\omega(1)},\ e^{-n},\ 2^{-2^n},\ (\log n)^{-\log n} \\ &\textbf{Non-Negligible:} && \frac{1}{2},\ \frac{1}{n},\ \frac{1}{n^{100}},\ \frac{1}{\log n},\ \frac{1}{\sqrt{n}},\ 1 - 2^{-n},\ \frac{1}{\log \log n} \end{aligned} \]

可忽略函数存在一些性质：考虑可忽略函数 \(\mu_1,\mu_2\)

  • 如果能找到 \(0\leq f(n)\leq\mu_1(n)\) 对足够大的 \(n\) 都成立，根据夹逼定理（？），那么 \(f\) 也是可忽略函数
  • 两个可忽略函数相加，或者与多项式相乘，结果也是可忽略函数

Definition of Computational Security

我们考虑对成功概率为 \(p\) 的攻击实施 \(t\) 次，至少成功一次的概率为 \(1-(1-p)^t\)，二项式展开放缩有

\[ 1-(1-p)^t\leq tp \]

我们记 \(n\) 为安全参数，若成功概率 \(p(n)\) 是可忽略函数，而攻击者的尝试次数 \(t(n)\) 是多项式，根据性质，\(tp\) 依旧是可忽略函数。因此当单次攻击的成功概率小到“可忽略”时，即使攻击者进行任意多项式次数的攻击，成功概率的提升依旧是可忽略的

以上，我们给出（渐进）计算安全的定义：如果对于任意高效攻击者 \(A\)，针对指定攻击类型的优势（即成功概率超出平凡猜测上界的部分）都是可忽略函数，那么称方案在该安全模型下是计算安全的

根据定义，它并不保证对于所有较小的安全参数都安全

Computationally Secure Encryption

我们希望将完美不可区分游戏改造成计算不可区分游戏。给出加密方案 \(\Pi=(\operatorname{Gen},\operatorname{Enc},\operatorname{Dec})\)，以及安全参数 \(n\)

我们记 Gen 生成随机 \(n\) 位的二进制密钥，原文为所有有限长度的二进制串 \(m\in\{0,1\}^*\)（或者与安全参数相关的 \(m\in\{0,1\}^{\ell(n)}\)，此时为固定长度私钥加密方案）

\[ k\leftarrow\operatorname{Gen}(1^n) \\ c\leftarrow\operatorname{Enc}_k(m) \\ m=\operatorname{Dec}_k(c) \]

定义加密方案安全性有两种方式：

  • Semantic Security（语义安全）：对于任何高效攻击者，以及任何能够高效计算的明文信息，攻击者看到密文所获得的帮助都至多是可忽略的
  • Indistinguishability（不可区分性）：攻击者无法区分两条候选明文的加密结果

这两者是意义等价的（不觉得很像完美保密性与完美不可区分性等价吗，它们的证明过程也是类似的）

对于后者，我们再次引入安全游戏

\[ \operatorname{PrivK}^{\mathrm{eav}}_{A,\Pi}(n) \]

玩法不变：攻击者给定两条等长明文，挑战者随机选择其中一条加密得到挑战密文 \(c\)，由攻击者根据 \(c\) 猜测 \(b\)，给出猜测结果 \(b'\)

我们定义：一个私钥加密方案具有窃听攻击下的计算不可区分性，当且仅当对于任意 PPT 攻击者 \(A\)，都存在一个可忽略函数 \(\operatorname{negl}(n)\)，使得

\[ \Pr[ \operatorname{PrivK}^{\mathrm{eav}}_{A,\Pi}(n)=1 ] \leq \frac12+\operatorname{negl}(n) \]

它有一个基于优势的等价定义（\(b'=0\) 同理）：

\[ \left| \Pr[b'= 1 \mid b = 0] - \Pr[b'= 1 \mid b = 1] \right| \leq \operatorname{negl}(n) \]

证明略，只要根据全概率公式代入推导即可：

\[ \Pr[ \operatorname{PrivK}^{\mathrm{eav}}_{A,\Pi}(n)=1 ] = \frac12+\frac12(\Pr[b'= 1 \mid b = 0] - \Pr[b'= 1 \mid b = 1]) \]

我们称上述加密方案是 EAV-secure 的，即在窃听攻击模型下的计算安全

PRG

我们需要一个由短密钥生成长字符串的工具，并且具有计算不可区分性。因此引入伪随机生成器 PRG：

\[ G:\{0,1\}^n\rightarrow\{0,1\}^{\ell(n)} \]

一方面，PRG 需要满足扩展性，即 \(\ell(n) > n\)；另一方面它需要满足伪随机性，对于任意 PPT 区分器 \(D\)，都存在可忽略函数 \(\mu(n)\)，使得

\[ \begin{aligned} &\left| \Pr[D(G(s))=1] -\Pr[D(r)=1] \right|\leq\mu(n) \end{aligned} \]

其中 \(s\xleftarrow{\$}\{0,1\}^n,\;r\xleftarrow{\$}\{0,1\}^{\ell(n)}\) 都是真随机字符串

一个安全的 PRG 具有以下特征：

  • 它是确定性算法，保证对于固定 \(s\)，输出固定 \(G(s)\)
  • 它的输出并不均匀随机，因为 PRG 的输入空间 < 输出空间
  • 它能抵御 PPT 攻击

PRG 是一个广泛使用的生成器，但它的存在性目前仍是计算复杂性假设（例如可由单向函数的存在性推出），尚未被无条件证明。我们目前基于这类假设认为它的安全性成立

利用 PRG 和 OTP，我们可以给出一个完整的计算加密方案。记 \(G\) 是一个安全的 PRG，给出加密方案 \(\Pi=(\operatorname{Gen},\operatorname{Enc},\operatorname{Dec})\)，以及安全参数 \(n\)

Gen 均匀生成 \(n\) 位密钥，核心的加解密算法为：

\[ c=G(k)\oplus m \\ m=G(k)\oplus c \]

它和 OTP 只在异或使用的字符串存在差异，但是它实现了使用较短的密钥加密较长的消息，得到计算不可区分的加密方案

Proof by Reduction

我们如何证明：在上述情境下，只要 \(G\) 是一个安全的 PRG，可以推导出 \(\Pi\) 是 EAV-secure？我们需要使用规约法

（也就是算法课程中在证明 Karp's 21 NP-complete problems 时使用的方法，思路非常接近）

简单来说，假设 \(X\) 是一个已知计算困难问题，\(Y\) 是另一个难度未知问题，我们证明：如果 \(Y\) 可以被高效的解决，则 \(X\) 可以被高效的解决（说明 \(Y\) 的难度不低于 \(X\) 的）；那么取逆否，既然 \(X\) 是一个已知计算困难问题，而 \(Y\) 的难度不低于 \(X\)，则 \(Y\) 也是个计算困难问题

此处我们证明：如果我们的 \(\Pi\) 方案可以被攻击，那么 PRG 可以被区分

假设存在 PPT Attacker \(A\) 能够以不可忽略的优势区分 \(\Pi\) 方案：

\[ \Pr[ \operatorname{PrivK}^{\mathrm{eav}}_{A,\Pi}(n)=1 ] = \frac12+\epsilon(n) \]

其中 \(\epsilon\) 是一个不可忽略的函数

现在我们需要构造新的 PPT Attacker \(A'\) 用来攻破 PRG，也就是给定一个长度为 \(\ell(n)\) 的字符串 \(x\)，判断它究竟来自 \(G(s)\) 还是 \(r\)

\(A'\) 怎么做呢？它接收 \(x\)，先运行 \(A\) 得到 \(m_0,m_1\)，然后随机选择 \(b\)，构造密文 \(c=x\oplus m_b\) 发给 \(A\)，并得到 \(A\) 的猜测 \(b'\)，然后按照下面的函数给出结果

\[ A'(x)= \begin{cases} 1,&b'=b\\ 0,&b'\neq b \end{cases} \]

（容易根据操作判断它属于 PPT Attacker）

如果真实输入来自 PRG，那么 \(c=G(s)\oplus m_b\)，哎这不就是 \(\Pi\) 方案下的 EAV 游戏分布吗，因此：

\[ \begin{aligned} \Pr[A'(G(s))=1] &=\Pr[b'=b]\\ &=\Pr[ \operatorname{PrivK}^{\mathrm{eav}}_{A,\Pi}(n)=1 ]\\ &=\frac12+\epsilon(n) \end{aligned} \]

如果真实输入来自真随机 \(r\)，那么 \(c=r\oplus m_b\)，哎这不是 OTP 加密吗，它满足完美不可区分性，因此：

\[ \Pr[A'(r)=1]=\frac12 \]

我们记

\[ \operatorname{Adv}^{\mathrm{prg}}_{A',G}(n) =\left| \Pr[A'(G(s))=1] -\Pr[A'(r)=1] \right| =|\epsilon(n)| \]

由此我们得到结论：如果存在 PPT Attacker \(A\) 能够以不可忽略的优势区分 \(\Pi\) 方案，那么就存在 PPT Attacker \(A'\) 能够以不可忽略的优势区分 PRG 输出

但是根据假设，PRG 是安全的，因此根据逆否结论，不存在 PPT Attacker \(A\) 能够以不可忽略的优势区分 \(\Pi\) 方案
