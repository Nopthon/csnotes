Lecture 4. Stream Cipher

流密码是一个确定性算法，它接受一个较短种子，并生成较长的看上去随机的 bit 序列

流密码具有以下特征

  • 它是确定性算法，保证对于固定 \(s\)，输出固定 \(G(s)\)
  • 它的输出并不均匀随机，因为 PRG 的输入空间 < 输出空间

流密码是实现 PRG 的工程手段，理想目标是实现计算不可区分性

形式化的，一个流密码由两部分构成：初始化算法 Init、生成函数 GetBits

我们记随机种子 \(s\)，可选的初始化向量 \(IV\)，初始化算法用于设置初始内部状态 \(st_0\)（比特数可以大于 \(s\)）

\[ st_0 := \mathsf{Init}(s,IV) \]

生成函数 GetBits 用于根据当前状态生成输出，并更新内部状态到下一状态

\[ (y_i,st_i) = \mathsf{GetBits}(st_{i-1}) \]

得到的序列 \(y_1||y_2||...||y_{\ell}\) 被称之为密钥流 keystream，符号 \(||\) 表示拼接，这里 \(y_i\) 可以是 1bit、1Byte 等

\[ G(s) = y_1||y_2||...||y_{\ell} \]

如果 \(G(s)\) 是安全 PRG，则要求对于任意 PPT 区分器 \(D\)，都存在可忽略函数 \(\mu(n)\)，使得

\[ \begin{aligned} &\left| \Pr[D(G(s))=1] -\Pr[D(r)=1] \right|\leq\mu(n) \end{aligned} \]

Stream Cipher Encryption

如何用流密码加密？类似于 OTP，只替换密钥流 \(y\) 的来源

\[ y \leftarrow \{0,1\}^{|m|} \qquad \Rightarrow y = G(k,IV) \]

它的优点在于计算效率高，适合硬件实现，且容易处理任意长度的消息（只需要生成与密文等长的密钥流）

它的使用注意点在于：

  • 类似于 OTP，密钥流不能重复使用，这会使得通过异或两条密文可以得到两条明文的异或结果
  • 它只保证保密性，不保证消息完整性，可以对密文 \(c\) 施加差分串的异或来精准修改解密结果的比特位，而不需要了解密钥。因此流密码加密还需要配合消息完整性校验机制

(Un)synchronized Mode

使用流密码来加密多条消息分为两种策略：同步模式依赖通信双方维护并同步一个持续更新的状态；非同步模式通过为每条消息引入随机初始化向量 \(IV\) 来避免状态依赖

  • Synchronized Mode

将消息和密钥流切分为若干连续的片段，每一段用于加密一条消息。每加密一条新的信息，就从上次停止的地方继续生成密钥流

\[ c_i = m_i \oplus y_i \]

优点是开销小（不需要 \(IV\)），适合连续通话；缺点是不适合偶发通讯，且状态丢失后难以恢复

  • Unsynchronized Mode

每加密一条新消息，发送方都会随机生成一个全新的 \(IV\)，并将其与密文一起发送。接收方用共享密钥和收到的 IV 来生成对应的密钥流

\[ st_i = \mathsf{Init}(k,IV_i) \]

再分别生成 \(y_i\)，加密 \(c_i = m_i \oplus y_i\)

优点是适合独立信息的加密，缺点是额外的 \(IV\) 传输开销，以及 \(IV\) 生成函数对算法安全性存在影响

LFSR

流密码中最经典的密钥流生成组件之一

考虑一个 \(n\) 阶 LFSR，它包含这样两个结构：

  • \(n\) 个串联的 1-bit 寄存器，存储的完整内容构成 LFSR 的当前状态
\[ st=(s_{n-1},\cdots,s_0) \]
  • \(n\) 个初始设定的反馈参数 \(c_i\in \{0,1\}\)，它决定了寄存器链中哪些寄存器参与

每次状态更新，依次进行下面的操作

  • 将最右侧的 \(s_0\) 输出，作为 \(y_i\)

  • 计算新 bit 位 \(f\)

\[ f = c_0 s_0 \oplus c_1 s_1 \oplus \dots \oplus c_{n-1} s_{n-1} \]
  • 将寄存器链的 \(s_i\) 右移一位，最高位更新为 \(f\)

这便是 LFSR 的构造

我们给出几个计算应用：

  • LFSR 存在周期性

注意到 \(n\) 阶 LFSR 的状态空间只有 \(2^n\) 种，只要某两个时刻的内部状态相同，其后续状态也一定相同。根据鸽巢原理，最多经过 \(2^n\) 次状态转移就会出现周期循环，其周期上界不超过 \(2^n\)（对于经典 LFSR，因为全零状态的下一步一定是全零状态，所以最长周期为 \(2^n-1\)）

并不是所有反馈系数都能实现最大周期

  • LFSR 可被重构攻击

具体的，使用 Berlekamp-Massey 算法等，只需要获取连续 \(2n\) 个输出 bit，就能重构内部状态（得到等价的初始状态和反馈系数）并预测之后的所有输出

恢复的可能不是原始 LFSR 而是等价 LFSR，可以保证生成相同的后续序列

首先我们读取前 \(n\) 位 LFSR 的输出，并将其作为等价的初始状态 bit（显然，如果我们将开始读取前 \(n\) 位输出作为 LFSR 的等价初始状态，那么初始状态会依次向右泵出）

\[ st=(s_{n-1},\cdots,s_0) \]

接下来，对于

\[ s_t = c_1 s_{t-1} \oplus c_2 s_{t-2} \oplus \dots \oplus c_n s_{t-n} \]

我们可以用接下来的 \(n\) 个输出得到对应的 \(n\) 个方程，解这个 \(\mathbb{F}_2\) 上的线性方程组可以解出所有的 \(c_i\)

Adding Nonlinearity

在经典 LFSR 中，我们将状态更新概括为一个矩阵乘法（它是线性计算）

\[ st_{i+1} = Ast_i \]

为了抵御重构攻击，必须在 GetBits 函数中引入非线性因素，比如：在状态更新的时候打破状态的线性移位；在生成 bit 的时候引入非线性映射

RC4

RC4 采用字节置换+指针交换来生成密钥流，它的内部状态包括：

  • S box：一个包含 256 个元素的数组 \(S[256]\)，每个元素是 8-bit 整数，并且初始化为 \(0\sim 255\) 的顺序排列（\(S[i] = i\)）
  • 两个 8-bit 指针 \(i,j\)

对于 Init 算法，选择一个 \(k\)，此处以 16-Byte 为例

我们创建一个辅助数组 \(T[i] = k[i \bmod 16]\)，内容为 \(k\) 的循环重复。接下来继续这样的操作：

WEP

WEP 是基于 RC4+CRC32 的早期 Wi-Fi 安全协议，标准的 64-bit WEP 使用 24-bit 的 IV 加上 40-bit 的 key，其中 IV 可变用于公开传输，key 固定用于私密保存

每次传输信息时，使用 \(IV || K\) 进行密钥流生成：\(y_i = RC4(IV_i||K)\)，用于对明文加解密

WEP 的脆弱之处显然在于 IV 的空间太小：全部的 \(IV\) 数量共有 \(2^{24}\) 个，只要出现某两次的 IV 相同，并且 key 未更换，就又会出现 Two-Time Pad 攻击相似的结果：可以得到两条明文的异或。根据生日悖论，只需要随机采样 \(2^{12}\) 个 IV 就会出现明显的重复率

为了试图抵御恶意的攻击，WEP 引入了 CRC-32 校验。CRC-32 是一个线性校验算法，我们在加解密时，将 \(m\) 换成与自己的 CRC-32 校验值的拼接，结果如下

\[ c = RC4(IV + Key) \oplus (m || CRC32(m)) \]

我们知道流密码容易受到 bit 翻转攻击（对密文施加差分），从而实现篡改数据包的内容并依旧通过 CRC-32 校验

因此 WEP 无法提供任何真正的消息完整性保护，而 CRC 的主要用途变成了检测随机传输错误

在 WEP 之后，又出现了 WPA/WPA2/WPA3 的安全机制，后两者基于 AES，符合现代安全要求

Suggestion

  • 不要使用不安全的流密码
  • 私钥加密时，建议优先考虑分组密码 Block Cipher 而不是流密码 Stream Cipher
